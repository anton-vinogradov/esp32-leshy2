# Leshy2 — Лист 2: MCU + шины

*Читать на: [English](c5-buses.md) · **Русский***

Два MCU и как от них расходятся все шины. Leshy2 — **двухчиповый** дизайн: **ESP32-S3** — главный мозг (ведёт UI, дисплей, все проводные радио, SD-карту и все шины); **ESP32-C5** — **сопроцессор**, добавляющий единственное, чего у S3 нет — нативный **Wi-Fi 5 ГГц** (плюс 2.4 ГГц, BLE и **802.15.4** / Zigbee / Thread). C5 — *чистый сопроцессор*: общается с S3 по выделенному линку и общую шину не трогает вообще. **Переключателя режимов нет** — устройством всегда владеет S3.

> ⚠️ Стадия проектирования. **Номера GPIO — предложенная карта**, ещё не сверенная с даташитами ESP32-S3 / ESP32-C5. До захвата подтвердить: boot-уровни страп-ног на обоих чипах; какие ноги дотягиваются до FSPI/SPI3/RMT/I²C через матрицу; что модуль C5 реально выводит ноги линка; номенклатуру N8R2 (quad-PSRAM). Функции зафиксированы; точные номера ног могут сдвинуться.

> 🗂️ *Папка называется `c5-buses/` по историческим причинам (прежний одночиповый дизайн). Теперь она про оба MCU.* Transcribe-ready чертёж этого листа перерисовывается под двухчиповую компоновку.

> 🔀 **Разбиение этапа 5.** **3× nRF24 и ИК теперь ведёт C5**, а не S3 — они уходят с SPI2 / 74HC138 / RMT у S3 на собственную SPI C5 (CS через 74HC139) и RMT, а **UART-мост прошивки S3→C5 снят** (C5 шьётся своим USB-C и берёт OTA по линку). Это уводит S3 на **30 / 36**, а C5 — на **~17 / 20**; см. [бюджет ног](../../docs/pin-budget.ru.md). C5 также **снимает `C5_BOOT`** (нативный USB сам входит в download), поэтому межплату пересекает только `C5_EN`. Новые опкоды **nRF / ИК / OTA-по-линку** принадлежат link-протоколу прошивки. Строки S3 ниже — **до-split карта**: `nRF24_CE`/`nRF24_IRQ`, ноги ИК, `C5_FLASH_TX/RX` и `C5_BOOT` переезжают/уходят при ре-захвате этого листа со сплитом плат.

## Два MCU

**U10 — ESP32-S3-WROOM-1U-N8R2** (главный мозг): двухъядерный Xtensa, 8 МБ flash + **2 МБ quad PSRAM**, нативный Wi-Fi 2.4 ГГц + BLE, u.FL → внешняя SMA.

- **Quad PSRAM — осознанно.** Octal PSRAM (варианты `R8`) забирает GPIO33–37 под свои доп. линии данных; **quad освобождает 35–37** — а GPIO33/34 *у модуля WROOM-1U вообще не выведены наружу* (см. таблицу ног), поэтому блок линка к C5 садится на 35–39, а две линии управления C5 уходят на расширитель. Нам под фреймбуфер 320×480×16 нужно ~300 КБ (двойная буферизация ~600 КБ), так что 2 МБ quad — с запасом; выбор диктует **бюджет ног, а не объём RAM**.
- Нативный USB на GPIO19/20. Serial-**консоль идёт через USB-Serial-JTAG** (не UART) — это освобождает UART0 под мост прошивки C5.

**U20 — ESP32-C5-WROOM-1U** (сопроцессор): одноядерный RISC-V, встроенный flash, нативный **Wi-Fi 2.4 + 5 ГГц + BLE + 802.15.4**, u.FL → своя внешняя dual-band SMA. Единственный ESP32 с нативным 5 ГГц. Встроенный flash занимает **GPIO15,16,17,18,20,21,22** (значит **GPIO19 свободна, а GPIO15 — нет**, вопреки прежним черновикам); нативный USB на GPIO13/14. Все радио C5 — внутри кристалла; внешнюю SPI-шину он не использует.

## Карта ног S3 (предложение)

После разбиения этапа 5 (nRF24 + ИК → C5, мост прошивки снят) S3 стоит на **30 / 36 — шесть свободных прямых ног**, и ни одна оставшаяся тайминг-линия не загнана на boot-страп. Таблица ниже — **до-split карта** (см. пометку этапа 5 выше); будущие *медленные* сигналы по-прежнему идут на второй PCA9555.

GPS теперь — внешний **M5 GPS Unit** на порту **Grove-UART**: линии S3 `GPS_UART_RX` / `GPS_UART_TX` (UART2, GPIO18 / GPIO47) выше выведены на этот Grove-UART-разъём вместо бортового модуля. Число ног не меняется — меняется только назначение. См. [Лист 5 — расширение](../expansion/expansion.ru.md).

## Карта ног C5 (предложение — сверить с даташитом)

~20 доступных GPIO. **Занято ~11**, просторно — C5 теперь только сопроцессор (без роли на общей шине, без мукса, без автономного режима).

| C5 GPIO | Цепь | Напр | Заметка |
|:--:|------|:--:|-------|
| EN (нога) | `C5_EN` ← S3 | in | reset + RC; в норме не гейтим |
| GPIO26 + GPIO28 | `C5_BOOT` ← S3 | in | ⚠ страп: **оба = 0 → download, оба = 1 → норма**; связать вместе к `C5_BOOT` (PCA9555 #2 P06) |
| GPIO27 | (страп) | — | ⚠ обязан быть подтянут **high** для валидной загрузки; не драйвится |
| GPIO23 | `LINK_SCK` ← S3 | in | SPI slave-клок (выделенный линк SPI3) |
| GPIO24 | `LINK_MOSI` ← S3 | in | |
| GPIO6 | `LINK_MISO` → S3 | out | несёт поток данных C5→S3 |
| GPIO8 | `LINK_CS` ← S3 | in | slave-select |
| GPIO9 | `DRDY` → S3 | out | единственная асинхронная линия C5→S3 |
| GPIO11 | `U0TXD` → S3 | out | UART0, путь прошивки + тест-пятак |
| GPIO12 | `U0RXD` ← S3 | in | UART0, путь прошивки + тест-пятак |
| GPIO13 / GPIO14 | `USB_D− / D+` | io | нативный USB → **отдельный разъём USB-C C5** (brick-safe восстановление/заливка/дебаг) |

C5 — чистый SPI-slave на выделенном линке плюс пути прошивки/USB — ничего на общей шине, поэтому нет ни возни с не-страп ногами, ни риска контенции со стороны C5. ~9 ног в запасе под будущие задачи сопроцессора.

## Линк S3↔C5 — выделенный SPI3

Линк на **втором свободном SPI-хосте S3 (SPI3)**, уведён с общей шины радио/SD/дисплея — чтобы поток 5 ГГц-захвата C5 не конкурировал с трафиком радио/дисплея и чтобы на главной шине не было контенции двух мастеров. Единственный SPI-контроллер C5 целиком отдан этому линку (мукса нет — автономный дисплей, который его когда-то требовал, снят).

| Сигнал | Направление | S3 / C5 |
|---|---|---|
| `C5LINK_SCK` | **S3 → C5** | 35 / 23 |
| `C5LINK_MOSI` | **S3 → C5** | 36 / 24 |
| `C5LINK_MISO` | **C5 → S3** | 37 / 6 |
| `C5LINK_CS` | **S3 → C5** | 38 / 8 (+ wake) |
| `C5LINK_DRDY` | **C5 → S3** | 39 / 9 |
| `C5_EN` | **PCA9555 #2 → C5** | P05 / EN |
| `C5_BOOT` | **PCA9555 #2 → C5** | P06 / 26+28 |

**Обратный провод сверх DRDY не нужен.** Весь поток C5→S3 несёт `MISO` (тактирует всегда S3); `DRDY` — единственная асинхронная линия «есть данные / событие». Нюанс: ESP32-slave должен предзагрузить TX-буфер до того, как мастер начнёт тактировать, поэтому **`DRDY` заодно — строб готовности**: S3 стартует клок только после подъёма `DRDY`. Отдельной линии `ACK`/`HOST_READY` нет.

## Прошивка обоих чипов

- **S3:** по нативному USB (GPIO19/20). Консоль делит тот же порт через USB-Serial-JTAG. Кнопки `S3_BOOT` (GPIO0) + `RESET` (EN) форсируют download. **Главный USB-C** обслуживает S3 (заряд + прошивка/консоль S3); у C5 свой отдельный порт (ниже). USB-мукса нет.
- **У C5 свой разъём USB-C** (самый простой путь восстановления): нативный USB C5 (D−/D+, GPIO13/14) заведён на **отдельный коннектор**. **Brick-safe** — USB-Serial-JTAG C5 живёт в mask-ROM, поэтому этот порт перешьёт C5, даже если его прошивка мертва (нужно питание от аккумулятора / master ON — USB-power-path нет, так что «brick-safe» это про мёртвую прошивку, не про разряженный пак). Шьёшь, мониторишь и JTAG-дебажишь любую прошивку C5 с ПК напрямую — так гоняешь свои 5 ГГц / Zigbee-эксперименты и спасаешь битую заливку. VBUS этого порта — только на USB-detect + ESD, **не** источник питания/заряда.
- **Авто-OTA C5 (по линку):** обновление S3 несёт согласованный образ C5 и толкает его в C5 **по линку SPI3**; C5 сам прошивается из линка, держа оба чипа в синхроне без втыкания кабеля. Гейт по версии/CRC. *(Старый UART-мост S3→C5 на GPIO43/44 снят — разбиение этапа 5 потратило эти ноги на сторону nRF / ИК, а ручную прошивку закрывает свой USB-C у C5.)*

## 74HC138 — карта chip-select

| Выход | Chip-select | На листе SPI |
|:--:|------|------|
| Y0 | `SD_CS` | microSD |
| Y1 | `CC1101_CS` | sub-GHz |
| Y2 | `nRF24_1_CSN` | 2.4 raw #1 |
| Y3 | `nRF24_2_CSN` | 2.4 raw #2 |
| Y4 | `nRF24_3_CSN` | 2.4 raw #3 |
| Y5 | `LoRa_NSS` | SX1262 |
| Y6 | `LCD_CS` | дисплей ST7796 |
| Y7 | (нет) | idle / адрес deselect-all |

`G1` = +3V3, `G2B` = GND, **`G2A` = `HC138_EN`** (выход PCA9555, подтянут высоко = выкл на boot) — держит дешифратор выключенным весь страп-window; это boot-гейт, а не поштучный (I²C слишком медленный). Быстрый deselect = парковка `A/B/C` на **Y7**; проходить через Y7 между двумя выборами, чтобы не словить глитч на промежуточном адресе.

## Кнопки reset и boot

Физические кнопки: S3 **RESET** + **BOOT**, плюс **PTT** (push-to-talk) для рации. Вкл/выкл питания — **master-тумблер** (Лист 1); софт-кнопки питания нет, переключателя режимов нет.

- **RESET** — момент. между S3 **EN** и GND (10 кОм pull-up + 1 µF RC).
- **BOOT** — момент. с S3 **GPIO0** на GND; удержать BOOT + тап RESET форсирует USB-download.
- **PTT** — момент. на GND через PCA9555 #2 `P0.0`; INT будит S3, тот кеит SA868 и переводит аудио-мукс на микрофон.

У C5 кнопок нет — его `EN`/`BOOT` ведёт S3; ручной путь восстановления — его собственный порт USB-C (mask-ROM USB-JTAG, brick-safe).

## Заметки про общую шину (прошивка, не железо)

Одна шина SPI2 делится SD + радио + дисплеем, обслуживается по одному устройству за раз. Замеренная худшая занятость ~11–21% (почти всё — пачки записи на SD; радио + водопад < 0.5%), так что контенция — не аппаратная проблема, а решается в прошивке:

- **DMA + двойная буферизация** полных заливок кадра (единственная реальная цена — busy-wait CPU 30–60 мс), чтобы UI не залипал. DMA разгружает CPU; шина остаётся серийной, а плавность держится на FIFO радио.
- **Арбитр шины:** один мьютекс, чтения радио и скролл водопада в приоритете над полными перерисовками; вытеснять трансферы SD/дисплея на границе CS/чанка (деассерт, сходить к радио, вернуться).
- **Watchdog на SD-транзакции:** зависшая в GC-столле карта может держать общий `MISO` и ломать чтение радио — таймаут и reinit карты.

## Гочи

- **Quad PSRAM — несущая.** Только N8R2 (quad) освобождает GPIO35–37 (GPIO33/34 у модуля не выведены в любом случае); octal-PSRAM S3 под линк не влезает.
- **Дисциплина страпов.** Страпы S3 {0, 3, 45, 46}: GPIO45 освобождена eFuse (выше); GPIO3 = JTAG-sel (boot don't-care), годится под `LoRa_DIO1`. Страпы C5 {26, 27, 28} — 26+28 связать в `C5_BOOT` с **внешним pull-up на 3V3** (дефолт = normal boot; расширитель на PCA9555 #2 P06 тянет `C5_BOOT` low только для прошивки C5), 27 подтянуть high.
- **Прямые GPIO S3 после разбиения: 30 / 36.** Шесть свободных быстрых ног (линии nRF24 / ИК / моста прошивки ушли на C5). Медленные ещё влезают на PCA9555 #2.
- **Страпы закрыты у корня.** GPIO45 (VDD_SPI) **де-страплена eFuse** (см. шаг прошивки ниже), поэтому `CC1101_GDO2` сидит там обычным прерыванием без брик-риска. Страп GPIO46 удовлетворён тем, что вентиль 74AHC делает `nRF24_IRQ` idle-**low**.
- **eFuse-шаг прошивки (обязателен, необратим).** Прожечь `espefuse.py set_flash_voltage 3.3V` один раз до первого боя, в ROM-download (вход по GPIO0 — отдельный страп; стаб грузится в IRAM, поэтому чтение флеша при 1.8В во время прожига не мешает). Это навсегда освобождает GPIO45. **Только для 3.3В-модулей — N8R2 подходит; НИКОГДА на 1.8В-octal-варианте** (окирпичит). Сверять `espefuse summary`.
- **Интерлоки гейта рейлов (прошивка).** +3V3A выведен из +5V, поэтому `RAIL_EN_5V` off гасит и +3V3A **и HF-приём** — держать +5V on, когда нужен +3V3A. Перед гейтом +5V увести `WS2812` (GPIO1) и `IR_TX` (GPIO2) в low/Hi-Z, иначе их высокий back-питает мёртвый рейл через входной кламп буфера/драйвера.
- **Опрос vs прерывание.** `LoRa_DIO1` (GPIO3), `nRF24_IRQ` (GPIO46) и `CC1101_GDO2` (GPIO45) — настоящие прерывания; `LoRa_BUSY` остаётся на опросе по SPI.
- **Два порта USB-C, один источник питания.** Порт C5 — только данные (VBUS → USB-detect/ESD, не в систему); пакет заряжается только через порт S3 (BQ25887). Конфликта двух источников нет.
- **Сверить до KiCad:** что S3 реально `N8R2`; что модуль C5 выводит GPIO23/24; точную страп-таблицу C5; маршрутизацию RMT/FSPI/SPI3/UART через матрицу.
