# DEC-0029 — ESP32-C5 v1.2 production floor

- Статус: **Условное правило candidate C5; C5 не выбран (`DEC-0032`)**
- Дата: 2026-08-16
- Основание: владелец выбрал `IMP-0024/A` и подтвердил общий приоритет свежих ревизий hardware
- Этап: 4 — компоненты и BOM
- Затрагивает: `DEC-0028/PKG-0001`, target READMEs, ownership, firmware `ARC-0001`, procurement/manufacturing/test manifests

> `DEC-0032` переоткрыл architecture. Этот документ остаётся проверенным
> revision/qualification input только для будущего candidate, использующего
> ESP32-C5; он не выбирает C5 и не разрешает закупку или CAD.

## Решение

1. Production, release и qualification builds Leshy2 используют `ESP32-C5-WROOM-1U-N8R8` с silicon revision **v1.2 или новее совместимой и отдельно квалифицированной revision**.
2. Incoming inspection проверяет module specification identifier: `MD` для v1.2. Manufacturing self-test дополнительно записывает eFuse-reported revision в board manifest/evidence.
3. C5 v1.0 (`MC`) разрешён только в явно маркированных engineering samples. На них запрещены HUK/Key Manager и PSRAM encryption, peripheral-domain power-down остаётся выключенным, boot/TX default — off, а результаты не закрывают production/release qualification.
4. Tests, зависящие от исправленных v1.0 errata, повторяются на production v1.2 hardware.
5. `FLASH-938` и `ECC-833` остаются отдельными constraints и не считаются исправленными v1.2. Flash manual encryption выполняется при CPU ≤160 MHz; exact signature/security implementation проходит дальнейшее review.

`DEC-0029` повышает только production floor. Он не включает HUK, flash encryption, irreversible eFuse lockdown или закрытый update model. Owner-controlled signed images, developer firmware and physical recovery из `DEC-0013/0028` сохраняются.

## Общее правило свежих аппаратных ревизий

Для нового изделия stage 4 предпочитает newest stable manufacturer-supported revision на момент BOM freeze, если одновременно доказаны:

- production status и доступность exact revision/lot;
- совместимость package/pins/electrical/firmware/toolchain;
- errata не создаёт новый regression;
- повторены затронутые qualification/HIL tests;
- revision identity доступна incoming/manufacturing control.

Больший номер сам по себе не является qualification. Новая revision не подменяется автоматически, а проходит controlled requalification. Старая revision допускается как engineering/fallback только с явным manifest и ограничениями; она не становится production saving без zero-loss proof.

## Последствия

- procurement требует revision-committed C5 lots, а generic MPN quote без silicon identity недостаточна;
- firmware manifest и boot report различают production-qualified и engineering-only boards;
- будущая совместимая revision выше v1.2 предпочтительна после requalification, но не меняет target молча;
- exact architecture owners, pins, SDIO, power, RF and update boundaries не меняются.
