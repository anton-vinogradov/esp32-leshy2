# ⚠️ IMP-0024 — ESP32-C5 v1.2 production floor

- Статус: **Принято как `DEC-0029`; проведено ревью**
- Дата: 2026-08-16
- Основание: `BOM-0002`, current ESP32-C5 errata v1.1
- Затрагивает: `DEC-0028`, target READMEs, firmware `ARC-0001`, procurement/manufacturing identity, security/power test matrix

## Current state

Принятая atomic architecture фиксирует `ESP32-C5-WROOM-1U-N8R8`, silicon revision `≥v1.0`. Exact module MPN не кодирует revision; производство обязано проверять module marking/eFuse separately.

Current manufacturer errata показывает, что v1.2 исправляет три релевантных v1.0 defects: PSRAM read-after-write consistency, possible SRAM corruption after peripheral-domain power-down и HUK recovery failure без workaround. На v1.0 Key Manager не поддерживается. На v1.2 всё ещё нужны отдельные ограничения для `FLASH-938` и `ECC-833`; новая revision не отменяет security qualification.

## Options

### A — recommended: v1.2 production, restricted v1.0 engineering only

- production/release/qualification hardware requires v1.2;
- incoming/manufacturing test verifies module specification identifier `MD` and runtime eFuse revision;
- v1.0 (`MC`) may be used only as clearly labelled engineering samples;
- v1.0 samples forbid HUK/Key Manager and PSRAM encryption, keep peripheral-domain power-down disabled, boot with TX off and cannot produce release qualification evidence.

Consequences: stronger and more predictable production baseline without discarding early samples; procurement must obtain revision-committed lots and maintain separate manifests. Prototype availability remains flexible, but results affected by errata must be repeated on v1.2.

### B — retain `≥v1.0` for production

- accept both `MC` v1.0 and `MD` v1.2 production lots;
- implement available software workarounds and keep HUK/Key Manager out of the product contract.

Consequences: simpler procurement, but production retains a no-workaround HUK defect and revision-dependent memory/power behavior. Every release/test matrix must branch by silicon revision, and a v1.0 result cannot prove v1.2-only security facilities.

## Recommendation

Choose **A**. This is a new design with owner-controlled signed updates and a deliberate path from ordinary functions to controlled high-risk operation. Shipping known older silicon to save a procurement constraint is not a zero-loss saving; allowing it for restricted prototypes preserves schedule without weakening the product floor.

## Decision question

Принимаем вариант **A**: C5 v1.2 для production/release/qualification, а v1.0 — только ограниченные engineering samples с указанными запретами?

## Decision result

Владелец выбрал **A** и подтвердил общий приоритет свежих стабильных аппаратных ревизий. Результат зафиксирован в [`DEC-0029`](../decisions/DEC-0029-c5-v1.2-production-floor.md) и проверен cross-repository review `REV-0004C`.
