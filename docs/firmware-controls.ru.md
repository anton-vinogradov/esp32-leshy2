# Leshy2 — управление и firmware-соглашения

*Читать на: [English](firmware-controls.md) · **Русском***

Набор физических органов зафиксирован; бо́льшая часть удобства живёт в **firmware-соглашениях**.
Ревью покрытия сценариев (74 штуки) показало, что железный набор **достаточен** — сценария без
физического пути нет — но выявило **два блокера безопасности** и набор соглашений, без которых
почти все потоки деградируют. Это требования к прошивке, зафиксированы здесь, чтобы компоновка
и прошивка не расходились.

## Физические органы

| Орган | Где | Роль |
|---|---|---|
| **D-pad (5-поз.)** | перёд | Вверх / Вниз / Влево / Вправо / Центр(OK) — навигация |
| **BACK** | перёд | уровень вверх / отмена / (в активном TX) стоп |
| **OPTIONS** | перёд | контекстное меню режима |
| **Энкодер-колесо** (крутить + нажать) | лев. борт | колесо значения / скролла, контекстное |
| **F1 / F2** | лев. борт | контекстные функц. клавиши |
| **PTT** | прав. борт | передача рации (SA868) |
| **STOP** | прав. борт | аппаратный паник-стоп |
| **Мастер-тумблер** | низ | единственный настоящий вкл/выкл (жёсткий, рвёт пакет) |
| **RESET / BOOT** | низ | утоплены, только dev / прошивка |

Все кнопки кроме PTT (на PCA9555 #2) сидят на **третьем PCA9555 (0x22)**, читаются по I²C через один
общий INT. Следствие: быструю навигацию делать **кручением энкодера**, а не удержанием D-pad, и
таймить long-press / комбо с учётом задержки чтения экспандера. **Второго аппаратного энкодера нет**
(A/B тайминг-критичны, GPIO заняты).

## Блокеры безопасности (обязаны быть в прошивке)

1. **Корректное выключение.** Мастер-тумблер рвёт питание мгновенно (нет ship-mode), поэтому
   недописанный PCAP / лог побьётся. Дать **OPTIONS → «Выключить»** (и/или меню по long-BACK):
   flush SD, парковка всех радио, упорядоченный стоп S3 + C5, затем экран *«можно выключать тумблер»*.
   Бэкстоп: периодический flush + аварийный brown-out flush.
2. **Паник-стоп передачи.** Залипший TX (deauth, beacon-спам, джаммер nRF24 / CC1101 / LoRa, залипший
   PTT) при зависшем UI обязан гаситься без обесточивания. Ядровый обработчик **long-BACK (или долгое
   нажатие энкодера) = «стоп всех TX»** поверх любого экрана. Физическая кнопка **STOP** — выделенный
   аппаратный путь к тому же обработчику.

## Соглашения

1. **Роль энкодера жёстко контекстна** + постоянный экранный чип (VOL / TUNE / STEP / ZOOM): список →
   скролл (×10 на удержании), числовое поле → значение, спектр / водопад без звука → zoom, аудиорежим
   (Si4732 / FM / SA868-RX) → громкость. Дефолт «громкость» намертво НЕ фиксировать.
2. **Нажатие энкодера:** короткое = toggle крупно/точно или цикл цели; длинное = mute. Никогда две
   несвязанные функции на одном событии нажатия.
3. **long-BACK / long-ENC = стоп всех TX**, поверх любого экрана, в любом режиме (см. блокер 2).
4. **BACK:** одиночное = уровень вверх (в активном TX первое = стоп-TX); long = домой.
5. **«Выключить»** (блокер 1) — первоклассный пункт OPTIONS + long-press.
6. **OPTIONS + Влево / Вправо = глобальный пред. / след. режим**, всегда дублируется пунктом OPTIONS —
   комбо никогда не единственный путь.
7. **OPTIONS → Полоса** — канон смены полосы CC1101 315 / 433 / 868 / 915; шорткат Влево/Вправо только
   вне numeric-edit; текущая полоса всегда в шапке.
8. **Arm / fire раздельно.** TX / атаки — за отдельным жестом (long-press Центр или подтверждение в
   OPTIONS) + явный индикатор *«взведено»* (красный WS2812 + TX-LED); голый Центр в списке целей не
   запускает передачу.
9. **Числовой ввод** = единый виджет разрядного курсора (D-pad = разряд, энкодер = значение, нажатие =
   цикл шага 1 / 10 / 100) + пресеты частот / диапазонов и список CTCSS в OPTIONS.
10. **Модал подтверждения удаления** ставит фокус по умолчанию на «Отмена»; массовое удаление через
    OPTIONS → «Выбрать несколько».
11. **Ввод текста:** canned-messages / quick-replies + кнопка *«отправить GPS-позицию»* как перво-
    классный путь; char-wheel энкодером как резерв; **клавиатура с телефона — основной путь длинного
    текста** (явно сказать в UI). Авто-имена файлов / ИК-кодов (timestamp + GPS + режим); ручное
    переименование опционально.
12. Каждое **комбо (OPTIONS + направление) дублируется** пунктом OPTIONS и/или long-press — комбо
    только ускоритель (одноручность / перчатки).
13. **PTT активен только** когда радиорежим на переднем плане и взведён; в прочих инертен; дебаунс +
    минимальная длительность hold-to-talk; канал / CTCSS править только в RX.
14. Постоянный **баннер «TX активен»** при уходе с экрана атаки (дублировать аппаратный TX-LED на
    экране); OPTIONS → «Стоп всё».

## Клавиатура с телефона (без нового железа)

Длинный текст (сообщения Meshtastic, Wi-Fi-пароли, SSID, имена файлов) печатается на сопряжённом
телефоне — паттерн Apple TV — через радио, которое у устройства уже есть:

- **BLE-компаньон** (предпочтительно): устройство = BLE-периферия с характеристикой ввода текста;
  телефон пишет туда. Не занимает Wi-Fi во время атак. На iOS нужен мелкий апп (Android — Web
  Bluetooth в браузере).
- **Wi-Fi captive-portal** (резерв): устройство поднимает AP + мелкую веб-страницу с полем ввода;
  работает на любом телефоне без аппа, но занимает Wi-Fi-радио.

Char-wheel на D-pad остаётся оффлайн-резервом для короткого ввода.

## Заметка на bring-up

- **Подсветка** пока без ШИМ (`LCD_BL_EN` = вкл/выкл через медленный экспандер). Яркость — тумблер,
  пока не добавлен boost / токовый LED-драйвер + ШИМ-нога (решение на bring-up — см.
  [лист питания](../hardware/power/power.ru.md)).
