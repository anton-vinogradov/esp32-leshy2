# Leshy2 — Roadmap

*Читать на: [English](roadmap.md) · **Русский***

Куда движется **Leshy2** — портативный мультидиапазонный РЧ-наладонник с открытым кодом («полевой инструмент»). Это преемник [esp32-leshy](https://github.com/anton-vinogradov/esp32-leshy), прошивочного форка [ESP32-DIV](https://github.com/cifertech/ESP32-DIV). Причина новой платы проста: DIV и leshy не умели 5 GHz Wi-Fi. Leshy2 закрывает это так: оставляем зрелый мозг **ESP32-S3** и добавляем **ESP32-C5** как сопроцессор на 5 GHz. Цель — максимум возможностей в разумных пределах за честную цену; см. [разбор стоимости](bom.ru.md).

## 🧭 Где мы сейчас

- **Архитектура зафиксирована (2026-08-10): два чипа.** Это всё ещё **стадия дизайна** — **железо пока не собрано**.
- Шесть листов схемы существуют как **готовые к переносу спецификации (Markdown)**; SVG-чертежи перерисовываются под двухчиповую компоновку.
- **Дальше:** захват листов в **KiCad**, затем **разводка PCB**.
- 🔴 **Ворота перед заказом любой платы:** доказать **5 GHz-deauth на голом девките ESP32-C5**. Если deauth не выйдет, коронная фича C5 сжимается до пассивной разведки — и это хочется выяснить на плате за $10, а не на сборке за $140.

## 🧠 Разделение на два чипа

Одночиповую идею (один C5 на всё) отбросили. C5 — молодой кремний без LCD_CAM и с тесным бюджетом ног; S3 проверен и уже гоняет leshy. Поэтому роли разошлись:

| | **ESP32-S3-WROOM-1U-N8R2** — мозг | **ESP32-C5-WROOM-1U** — сопроцессор |
|---|---|---|
| Ядра / ОЗУ | 2× Xtensa, QUAD-PSRAM | RISC-V |
| Держит | UI, дисплей, **всё проводное радио**, SD, шины, 2.4 GHz Wi-Fi + BLE (нативно) | нативный **5 GHz** Wi-Fi (единственный ESP32 с ним) + 2.4 / BLE / 802.15.4 (Zigbee/Thread) |
| Ноги | **36 / 36 — потолок** | ~11 / 20 |
| Прошивка | USB-C **J1** (заряд + данные) | шьётся от S3 по UART0 (авто-OTA) **и** свой USB-C **J2** (только данные, brick-safe) |

**Линк:** выделенный **SPI3 + DRDY** (строб готовности) между S3 и C5. S3 остаётся единой точкой управления; C5 — чистый агент 5 GHz.

## 🚦 Фазы

### 1. Архитектура — готово

- [x] Два чипа: **мозг S3** + **сопроцессор C5 на 5 GHz**, линк по выделенному SPI3 + DRDY
- [x] Общая шина **SPI2** (S3 FSPI, 80 MHz): microSD + CC1101 + 3× nRF24 + SX1262 + ST7796, chip-select через дешифратор **74HC138**
- [x] Медленное управление на **трёх PCA9555**: 0x20 (радио / контроль дисплея), 0x21 (PTT / гейты рейлов / SP4T / гнездо наушников), 0x22 (UI-кнопки)
- [x] Прямые линии прерываний вне расширителей: LoRa DIO1, nRF24 IRQ (через вентиль 74AHC), CC1101 GDO2 carrier-sense (GPIO45 де-страплена через установку flash-voltage в eFuse), CC1101 GDO0
- [x] Набор РЧ: **3× nRF24L01+PA/LNA** (2.4 raw), **CC1101** (голый + кварц + балун) → **SP4T SKY13414-485LF** + 4 матч-сети (315 / 433 / 868 / 915), **SX1262** (E22-900M22S, +22 dBm LoRa), **Si4732-A10** (HF/CB/FM, только RX), **SA868-U** (433 / 446 голос, 2 Вт)
- [x] Аудио: аналоговое моно → **PAM8302** класса D → динамик + гнездо наушников; MCU не в аудиотракте
- [x] Дисплей **ST7796 320×480 IPS** по SPI (не 8080 / AMOLED — у C5 нет LCD_CAM; водопад едет на аппаратном вертикальном скролле панели)
- [x] **GPS** (u-blox, UART, на плате); **2× Grove I²C** + юнит RFID2
- [x] Питание: **2S 2×18650**, boost BQ25887 (5 В→8.4 В, без PD), защита S-8252A, MP2315 +5 В, TLV62569 +3V3, TPS7A2033 +3V3A, master-тумблер; рейлы гейтятся в idle
- [x] **9 антенн**, РЧ-свитча между трактами нет: S3 2.4 (внешняя SMA), C5 dual 2.4/5, 3× nRF24, CC1101, Si4732 телескоп, SA868 UHF, SX1262 LoRa
- [x] Органы ввода: RESET, BOOT, **PTT**, поворотный энкодер; master-тумблер = питание

### 3. 🔴 PoC 5 GHz-deauth — ворота перед PCB

- [ ] На голом **девките C5**: скан / снифинг 5 GHz, флуд beacon + probe и **попытка deauth**
- [ ] Записать честный ответ (работает / только PoC / никак) — он задаёт, что C5 вправе обещать до того, как мы закажем медь

### 4. Разводка PCB

- [ ] **4-слойная** плата (JLCPCB JLC7628, импеданс ±10 %)
- [ ] РЧ-дорожки с контролем импеданса; буферные конденсаторы прямо рядом с модулями nRF24
- [ ] Размещение: антенны сверху; внешняя SMA для тракта 2.4 S3
- [ ] Земля питания и РЧ

### 5. Первая итерация PCB

- [ ] Заказать, спаять, собрать (шаги мейкера)
- [ ] Запуск (bring-up): шины питания, загрузка S3, загрузка C5, линк SPI3, затем каждая шина
- [ ] **Честное ожидание: 1 рабочая итерация + 1 доводочная**

### 6. Прошивка

Три части: портировать мозг, добавить агент 5 GHz и склеить их.

- [ ] **Портировать leshy** (код S3 уже работает — в основном bring-up на новой плате)
- [ ] **Агент C5 на 5 GHz**: скан / снифинг / флуд beacon-probe (+ deauth, если PoC скажет «да»)
- [ ] **Протокол линка** по SPI3+DRDY: S3 ведёт, C5 отвечает
- [ ] Драйверы: 3× nRF24, CC1101 (+ выбор диапазона SP4T), SX1262, Si4732, SA868-U, u-blox GPS, PCAP на microSD
- [ ] Ограничения мощности LoRa по регионам в прошивке (EU433 +10 dBm, EU868 +14 dBm, 869.4–869.65 MHz +27 dBm при 10 % duty, US915 +30 dBm с перескоком)
- [ ] Ввод текста по BLE (длинный текст набирается на телефоне)

### 7. Настройка антенн (VNA)

- [ ] Настроить каждую из 9 антенн с помощью **VNA** (ручной шаг мейкера)

### 8. Полевые испытания

- [ ] Время работы (лёгкий ~9 ч, активный ~3.6 ч, пики TX ~2.5 ч)
- [ ] Дальность: голос SA868 (~3–5 км на открытой), Meshtastic (город 2–5 км, прямая видимость 10–15 км)
- [ ] Проверка каждого РЧ-тракта в реальных условиях

## 🧠 Roadmap прошивки — бесплатные фичи

Кремний уже оплачен; это чисто софтовые выигрыши, которые планируем добавлять со временем.

- **Evil Portal / Karma / rogue-AP** — captive-portal и karma-атаки на 2.4 GHz (S3)
- **Флуд BLE-advertising + снифинг 802.15.4 / Zigbee** (C5)
- **Авто-затемнение подсветки** — дисплей — крупнейший расход в простое; гасим, когда ничего не меняется
- **LoRa Rx Boosted Gain** — настройка SX1262, +15–30 % дальности бесплатно
- **Dirty-rect UI** — перерисовываем на ST7796 только изменившееся
- **Сглаживание общей шины** — DMA + двойной буфер + прошивочный **арбитр шины** (0 ног) + **watchdog SD**; контенция общей SPI2 — фантом (~11–21 %, почти всё — пачки SD), поэтому фикс софтовый, а не лишняя медь

## 🧱 Намеренно вне области — честные потолки

- **5 GHz только уровня разведки** — скан, снифинг, флуд beacon / probe; **deauth — вопрос PoC** (см. фазу 3). Ни инъекции, ни захвата WPA-handshake, ни monitor+inject — для этого нужен Linux, которого мы избегаем ради времени работы. **2.4 GHz deauth работает** (на S3).
- **Si4732 только на приём** — слушать HF / CB / FM, TX там нет.
- **Одно радио в единицу времени** — тракты делят шину и внимание оператора; это не одновременный многорадийный SDR.
- **Аудио моно.**
- **Это не HackRF** — нет непрерывного широкополосного захвата, нет произвольного TX.
- **Широкополосного глушения нет** — это незаконно (US Communications Act §333, EU RED).
