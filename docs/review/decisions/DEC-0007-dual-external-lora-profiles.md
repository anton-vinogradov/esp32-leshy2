# DEC-0007 — оба внешних LoRa-варианта: Cardputer Cap и сменный модуль

- Статус: **Принято владельцем проекта**
- Этап: 2 — scope; электрическая и механическая реализация проверяется на этапах 3–6
- Дата принятия: 2026-08-15
- Принимает: `IMP-0007`, `IMP-0008`
- Затрагивает: `C-LORA-*`, `C-GPS-*`, expansion, BOM, питание, корпус и firmware

## Решение

Новый Leshy2 не несёт LoRa-модуль и его RF-тракт на основной PCB. Вместо этого поддерживаются **оба подключаемых варианта** через единый внешний профиль `EXT-RF14`:

1. прямое подключение M5Stack Cap LoRa-1262 `U214` с SX1262 и GNSS AT6668;
2. сменный LoRa-модуль на carrier, обязательный reference-вариант — E22-900M22S для сохранения диапазона 850–930 MHz.

Первичная реализация использует один физический слот и один общий host/backend contract. Одновременно установлен и активен только один LoRa backend. Второй физический LoRa-слот, одновременная работа двух SX1262 и diversity не входят в принятое решение: это отдельная возможность с дополнительными pin/power/RF/isolation требованиями.

## Функциональная эквивалентность

- U214 предоставляет готовый профиль LoRa+GNSS в диапазоне 868–923 MHz.
- E22 reference carrier сохраняет legacy-окно 850–930 MHz и прямое SPI-управление SX1262.
- Ограничение конкретного U214 не считается ограничением Leshy2: UI и firmware применяют диапазон и channel plans обнаруженного модуля.
- UART/AT LoRaWAN Units могут получить отдельный backend после проверки, но не заменяют raw SX1262 reference profile.
- Ни один модуль не получает blanket-совместимость по одному совпадению connector или радиочипа.

Полная функциональная эквивалентность считается доказанной только после реализации и приёмки U214 и широкополосной E22 carrier. До этого решение фиксирует scope, а не готовое устройство.

## Связь с GNSS

`DEC-0006` сохраняется: отдельный M5Stack Unit GPS v1.1 через защищённый UART `PORT.C` остаётся поддерживаемым GNSS-аксессуаром. При установленном U214 его встроенный AT6668 является вторым поддерживаемым вариантом и позволяет не подключать отдельный GPS Unit.

Firmware выбирает один активный GNSS backend. Одновременное sensor fusion двух внешних GNSS не принято и не является скрытым требованием.

## Обязательные ограничения реализации

- `EXT-RF14` должен быть совместим с документированным pinout U214; точные connector, orientation, retention и power direction подтверждаются до схемы.
- Слот питается через управляемую защиту и по умолчанию выключен.
- Подключение выполняется при снятом питании, пока hot-plug не доказан испытаниями.
- TX запрещён до идентификации backend, выбора разрешённого региона, подтверждения антенны и прохождения гейтов `DEC-0003`.
- Capability descriptor модуля задаёт диапазон, channel plans, модуляции, предельную мощность, наличие GNSS и revision driver.
- Снятие или отказ модуля немедленно прекращает TX и корректно закрывает активную сессию.
- На этапах 3–6 обязательны pin/power budget, bus coexistence, RF coexistence, EMC, thermal, механические и antenna safety tests.

## Стоимость

Из base device удаляются E22, `U27`/T/R-обвязка, бортовой LoRa SMA и пигтейл. Остаются цена `EXT-RF14`, power/protection и механического удержания.

U214 за `$14.50` предварительно дешевле legacy-связки E22+антенна (`~$9`) и отдельного GPS Unit (`$9.95`) примерно на `$4.45` до учёта connector/mechanics. E22 carrier служит гарантией диапазона; её полная цена должна быть доказана котировкой по `DEC-0005`.

## Результат scope

- бортовой LoRa: **нет**;
- Cardputer Cap U214: **поддержать**;
- сменная LoRa carrier: **поддержать**;
- E22-900M22S carrier: **обязательный wideband reference profile**;
- активных LoRa backend одновременно: **один**;
- отдельный M5 GPS Unit: **сохраняется как альтернативный GNSS backend**.
