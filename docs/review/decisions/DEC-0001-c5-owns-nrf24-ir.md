# DEC-0001 — целевое владение C5 для 3× nRF24 и IR

- Статус: **IR-часть остаётся принятой; nRF24-часть переоткрыта владельцем (`FND-0028`, `IMP-0021`)**
- Дата: 2026-08-15
- Затрагивает: hardware и firmware

## Историческое решение

В исходном решении ESP32-C5 был аппаратным и программным владельцем:

- трёх радиомодулей nRF24L01+;
- IR-передатчика;
- IR-приёмника.

ESP32-S3 не подключается к их локальным управляющим линиям и обращается к функциям nRF24/IR только через межпроцессорный контракт.

После `FND-0028`, `DEC-0022` и `DEC-0023` эта граница сохраняется только для IR. Для nRF24 документ является историческим входом одного варианта и не запрещает S3-heavy/balanced решение, прошедшее общий demand model.

## Следствия

- SPI/CS/CE/IRQ nRF24 назначаются вместе с physical owner на этапе 3.
- RMT/GPIO для IR находятся на стороне C5.
- UI, политика безопасности и команды остаются под управлением S3.
- Старые S3-сети IR в tsCircuit/KiCad должны исчезнуть; nRF24-сети остаются legacy-кандидатом до принятия этапа 3.

## Открытый блокер реализации

Транспорт S3↔C5 не выбран. Текущая legacy-идея «C5 как SPI-slave плюс C5 как SPI-master для nRF24» конфликтует с единственным GP-SPI контроллером ESP32-C5; см. `FND-0001`.

До закрытия `FND-0001` нельзя утверждать, что C5-heavy nRF24 вариант реализуем выбранным набором компонентов и шин.

## Последующее переоткрытие

После требования сохранить полный native feature set всех трёх nRF24 проведён `AUD-0003`. Он показал более дешёвый на текущем составе предварительный вариант с владельцем S3 и снятием конфликта единственной GP-SPI C5. Поэтому назначение nRF24 на C5 больше не является окончательным входом этапа 3. `DEC-0022` отложил ответ до freeze; после `DEC-0023` **⚠️ `IMP-0021`** сравнивается с C5-heavy и balanced/modular вариантами на полном demand model.

IR остаётся на C5. `DEC-0023` завершил wishlist gate: target README больше не показывает C5 как принятого nRF24 owner, а этап 3 сравнивает минимум три варианта до нового ownership decision.
