# DEC-0003 — безопасный TX-дефолт

- Статус: **Принято владельцем проекта**
- Этап: 2 — возможности и исключения
- Дата принятия: 2026-08-15
- Источник предложения: `IMP-0001`
- Затрагивает: hardware safety contracts, firmware, UI и тесты

## Решение

1. После power-on, reset, brownout, watchdog reset и обновления прошивки все передатчики выключены.
2. Каждый инструмент «Лаборатории» при входе и после любого reset разоружён.
3. Первая передача использует консервативный профиль мощности, полосы и duty, определяемый отдельно для каждого радиотракта на этапе 2.
4. Аппаратный максимум никогда не является глобальным или неявным дефолтом.
5. Максимальная доступная мощность включается только явным действием пользователя для конкретного передающего сценария; выбранное значение и активное состояние TX должны быть видны в интерфейсе.
6. Акт о ненападении обязателен, но не заменяет технические interlock, safe-state и аварийное выключение TX.
7. Региональный профиль, ручной выбор ограничений или их сочетание определяются после порадиочастотной проверки возможностей; это решение не обещает автоматически определить применимое право.

## Отклонённый legacy-вариант

Правило «TX-мощность по умолчанию на максимуме, а install-соглашение является единственным гейтом» не наследуется.

## Обязательные проверки зависимых артефактов

- тест каждого reset-пути подтверждает отсутствие передачи до явного включения;
- тест каждого Lab-инструмента подтверждает начальное состояние `DISARMED`;
- ни один экран или сохранённая настройка не может неявно восстановить максимальную мощность после reset;
- повышение мощности требует отдельного подтверждаемого пользовательского действия;
- STOP и аварийный путь выключения должны иметь приоритет над UI и прикладными задачами.

Конкретные значения консервативных профилей и достижимость аппаратного STOP остаются предметом следующих требований и архитектурных этапов.
