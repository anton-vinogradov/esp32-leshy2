# ⚠️ IMP-0022 — latched hard-STOP tree с перезапуском обоих MCU

- Статус: **Принят вариант A как `DEC-0024`; проведено ревью**
- Этап: 3 — системная архитектура и владение
- Дата: 2026-08-16
- Основание: `DM-SAFE-01`, `FND-0007`, `IMP-0010`, `PIN-0001`
- Затрагивает: оба MCU, все встроенные и внешние TX paths, power tree, recovery, UI session

## Контекст решения

Аппаратный STOP должен прекратить передачу при зависшем S3, зависшем C5, остановленном I²C, повреждённом UI, незавершённом update и подключённом TX-capable аксессуаре. Программная команда, GPIO экспандера или уведомление двум задачам этого не обеспечивают.

У S3 и C5 есть встроенные radio, которым нельзя независимо и универсально запретить RF-передачу одним внешним `TX_EN`, сохранив сами MCU работающими. Для внешних CC1101, 3×nRF24, voice backend, IR emitter и U214 также нельзя полагаться на последний записанный регистр при зависшем owner. Поэтому сильная реализация STOP затрагивает reset/power, а не только software state.

## Вариант A — рекомендуемый hard STOP

Физическая кнопка асинхронно устанавливает независимую аппаратную защёлку `TX_KILL`:

1. аппаратно удерживает `EN` S3 и C5 в reset;
2. отключает отдельные switched rails всех TX-capable внешних RF/IR/accessory domains либо их эквивалентные hardware inhibit paths;
3. независимо принуждает voice `PTT` в RX и снимает разрешение PA до исчезновения питания тракта;
4. принуждает IR driver в off независимо от C5;
5. имеет собственную видимую индикацию защёлкнутого STOP, не зависящую от UI;
6. не снимается отпусканием кнопки и не может быть снят одной firmware-командой;
7. re-arm разрешён только после отпущенного STOP отдельным физическим действием или power cycle; после re-arm устройство проходит обычный boot с TX-default-off и без восстановления старой TX lease.

Цена этого свойства: активная сессия, UI state и приём прекращаются, оба MCU перезапускаются. Журнал может восстановить только записи, уже сброшенные в энергонезависимое хранилище; STOP нельзя задерживать ради записи лога.

## Вариант B — selective TX inhibit

S3/UI и часть приёмников продолжают работать, а STOP управляет отдельным inhibit/power gate каждого передающего тракта. Для внешних модулей это требует больше switches/gates и доказательства безопасного состояния каждого exact module. Для встроенных S3/C5 radio потребуются дополнительные RF-front-end barriers или доверие к исправному firmware/MCU state. Поэтому вариант B сложнее, дороже и не даёт той же независимой гарантии для integrated radio.

## Рекомендация саморевью

**Принять вариант A.** Он превращает STOP в понятный последний рубеж: потеря текущей сессии допустима, продолжение неизвестной передачи — нет. Exact latch/supervisor/load-switch BOM и partition rails выбираются на этапе 4 после power budget, но логическая топология становится hard constraint уже для всех layouts этапа 3.

Вариант B допустим только как отдельное будущее улучшение поверх A для сохранения receive-only частей, но не как замена hard STOP.

## Acceptance boundary при принятии A

- STOP latency задаётся и измеряется от физического контакта до deassert/inhibit каждого TX domain;
- fault-open/short и loss-of-power состояния safety chain документируются; одиночный I²C/software fault не отменяет STOP;
- attached accessory получает питание/разрешение только через квалифицированный STOP-dominant профиль;
- re-arm не восстанавливает предыдущий канал, мощность, payload, target или TX lease;
- HIL включает зависание обоих MCU, active TX, brownout, update, expander/bus fault и accessory fault;
- actual-TX detection из `DM-SAFE-02` остаётся отдельным требованием: STOP tree не подменяет доказательство фактического TX.

## Решение владельца

Вариант A принят как `DEC-0024`. Вариант B не является эквивалентной заменой hard STOP.
