# IMP-0051 — target README как целевой product site

- Статус: **Принято владельцем; реализовано как `DEC-0060`**
- Дата: 2026-08-17
- Finding: [`FND-0072`](../findings/FND-0072-target-readmes-contained-engineering-chronology.md)
- Затрагивает: оба репозитория, EN/RU entrypoints, documentation regression

## Контекст

Target README должны постепенно формировать документ готового продукта, но
стали повторять историю проработки. Удалять эту историю нельзя: она нужна для
трассируемости. Оставлять её на главной странице тоже нельзя: GitHub entrypoint
становится журналом архитекторов вместо понятного сайта Leshy2.

## Принятый вариант

- Корневые README отвечают на вопросы «что это», «что умеет», «как устроено»,
  «как безопасно работает» и «где техническая спецификация».
- `docs/status/current-state.*.md` отвечает на вопрос «что уже доказано и что
  открыто сейчас».
- `docs/review/` хранит решения, источники, находки и проверки.
- Target page может показывать принятую принципиальную diagram, exact MPN и
  pin mapping, но не пересказывает историю их выбора.
- Длинные технические группы сворачиваются или переносятся в atlas, чтобы
  entrypoint читался на мобильном экране.
- EN/RU пары меняются атомарно; hardware и firmware ссылаются друг на друга.

## Решение владельца

Владелец ответил `го` на предложение перенести инженерную хронику из target
README, оставить её в current-state/review и начать формировать чистое описание
готового продукта. Вариант принят без изменения product scope.
