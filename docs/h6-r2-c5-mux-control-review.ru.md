# H6 · Проверка управления мультиплексором USB/SDIO C5

[Главная](../README.ru.md) · [Дорожная карта](roadmap.ru.md) · [English](h6-r2-c5-mux-control-review.md)

Статус на 2026-09-14: **дефекты установленной схемы управления/доменов питания остаются открытыми; кандидат исправления проходит исполняемую проверку, но не внедрён и не выбран для производства.** Эта проверка не разрешает производство и не подтверждает временные параметры переключения. Исправление классов трассировки и нативных имён защищает общую пару данных, но не исправляет описанную здесь цепь управления. Отдельный срез платы опубликован в [текущей трассировке](h6-r2-current-routing.ru.md).

## Что должна делать схема

C5 GPIO13 — это USB D− / SDIO DAT3; GPIO14 — USB D+ / SDIO DAT2. Мультиплексор FSUSB42 выбирает сервисный USB при `SEL=0`, рабочий SDIO при `SEL=1` и отключает обе ветви при `OE=1`.

[Контракт мультиплексора](../hardware/architecture/c5-sdio-service-mux-contract.json) требует асинхронного аппаратного захвата сервисного владения, удержания Hub в reset при сервисном владении и интервала отключения перед сменой ветви **в обоих направлениях**. Владение можно снять только при отсутствии сервисного VBUS, активном reset C5, подтверждении reset/высокоимпедансного состояния Hub и явном запросе always-on контроллера. Это требования, а не доказательство их выполнения текущей схемой.

## Подтверждённые физические соединения

[Переопределения топологии R2](../hardware/ecad/h2-r2-topology-overrides.json), [реестр нативных сетей](../hardware/ecad/generated/H2-R2-native-net-ledger.json) и принадлежность площадок нативных UI/RF подтверждают следующие связи:

| Сигнал | Точные текущие выводы / назначение |
| --- | --- |
| `C5_MUX_SEL` | Только UI U22.2 и R92.1; R92.2 подключён к земле. **Активного драйвера выбора нет.** |
| `C5_MUX_SEL_REQUEST` | RF U111.15 (`P12`) → J12.55 / UI J18.55 → R87.1. RF R255.1 также задаёт подтяжку запроса; оба резистора возвращаются на землю. Это не сеть SEL. |
| `C5_SERVICE_PATH_ACK` | RF U111.16 (`P13`) → J12.56 / UI J18.56 → U17.1. RF R256 задаёт подтяжку к нулю. |
| `AON_SERVICE_RELEASE_REQ` | RF U111.17 (`P14`) → контакт M1.57 → UI U19.5; один из входов аппаратно обусловленного снятия владения. |
| `C5_SERVICE_OWNED` | UI U18.5 → U19.9, транзистор reset Hub Q2.5 и M1.58 → RF U111.18 (`P15`, наблюдение). |
| `C5_MUX_DISABLE` / OE | UI U17.4 → U22.10, транзистор reset C5 Q3.1 и R91.1; R91.2 подключён к земле. |

Здесь M1 — соединение UI J18 с RF J12. U111 — расширитель TCA9535 always-on контроллера безопасности, а не прямой выход прошивки C5/Hub/S3. Разделение имён REQUEST/SEL само по себе не задаёт отсутствующий буфер: конкретного драйвера аппаратно разрешённого выбора в проверенной схеме нет.

Текущие соединения инверторов U17 и NAND U19 дают:

```text
ACK_N = NOT ACK
DISABLE_N = NOT (OWNER AND ACK_N)
OE = OWNER AND NOT ACK
```

| OWNER | ACK | Текущий OE | Следствие |
| ---: | ---: | ---: | --- |
| 0 | 0 или 1 | 0 | Нельзя командой отключить ветви в рабочем режиме / после снятия владения. |
| 1 | 0 | 1 | Обе ветви отключены; Q3 удерживает C5 в reset. |
| 1 | 1 | 0 | Выбранная ветвь подключена; OWNER продолжает удерживать Hub в reset. |

Таким образом, SEL без драйвера, с подтяжкой к нулю, не может выбрать рабочий SDIO. Отдельно от этого уравнение OE не обеспечивает требуемый интервал отключения в обоих направлениях. При асинхронном захвате сервисного владения с ещё высоким ACK этот путь OE также не включает reset C5. Простое соединение REQUEST с SEL или переименование сетей данных эти дефекты не закрывает.

Существующие [проверки цифровых интерфейсов](../hardware/verification/h3_r2_digital_interfaces.py) проверяют подтяжки, выводы данных и наличие компонентов защёлки/reset. Они не доказывают наличие активного драйвера SEL или таблицу переходов. Нулевой нативный DRC также не подтверждает работоспособность управления.

## Кандидат исправления, не установленная схема

[Исполняемая модель](../hardware/verification/c5_mux_control_candidate.py) и [регрессионные тесты](../hardware/architecture/tests/test_c5_mux_control_candidate.py) отделяют проверку логики/порядка действий от реальных электрических и временных доказательств. Обозначения: `O=OWNER`, `R=REQUEST`, `A=ACK` в значении **разрешения подключить**, `L=RELEASE_REQ`, `P=RUN_PERMIT`, `F=FAULT_ASSERT_N`:

```text
SEL = R
VALID = NOT (O AND R)
OE = NOT (A AND VALID AND P AND F)
HUB_HOLD = O OR L OR NOT R
```

Так можно командой отключить любой режим, аппаратно запретить SDIO при сервисном владении и всегда удерживать Hub в reset при выборе USB. Существующие независимые цепи reset от KILL/fault сохраняются. Новые сигналы M1 или GPIO не нужны. Кандидат сохраняет NAND обусловленного снятия владения, меняет назначение второго NAND U19 и обоих инверторов U17, добавляет один двойной четырёхвходовый NAND с bypass. Нагрузку выходов ещё нужно проверить до выбора установленной комбинации логики/подтяжек.

U17 формирует `NOT O` и `NOT L`; **нельзя подставлять U18.Q_N вместо `NOT O`**. Таблица SN74LVC1G74 допускает HIGH одновременно на Q и Q_N при одновременном активном preset и clear. Схема Hub на прямом Q_N тогда могла бы снять reset. Инверсия именно Q устраняет этот контрпример, но не остальные требования к асинхронным задержкам защёлки. [Таблица TI 8-1](https://www.ti.com/lit/ds/symlink/sn74lvc1g74.pdf).

Порядок действий не менее важен:

- Переход к USB: при горячем подключении сервисное владение сначала отключает активный SDIO и удерживает оба процессора в reset. Явно записать `A=0`, удержать Hub через `L=1`, установить reset/high-Z, затем сменить `R=0`; разрешить подключение через `A=1` только после установления сигналов. Смена R при оставшемся A=1 отвергается.
- Возврат к SDIO: при отсутствующем сервисном VBUS установить `L=1` и `A=0` до смены R. Выбрать `R=1`, снять владение только при выполнении существующих аппаратных условий, затем подключить через `A=1`. Удерживать Hub после снятия reset C5 не меньше интервала strap 3 мс; снимать L только после требуемого условия запуска/готовности. Нужны отдельные подтверждённые записи расширителя, не одна совмещённая запись выбора/разрешения.
- Маркеры ожидания в модели — **допущения**, не измеренные задержки. Повреждённая прошивка, обрыв записи и неудачная I2C-транзакция требуют настоящего сервисного менеджера Safety, входа в ROM и обработки ошибок с отключением; эта модель такой менеджер не реализует.

## Домены питания и проверка фабричных компонентов

У текущего FSUSB42 есть независимый дефект: абсолютный максимум SEL/OE равен **его собственному VCC**, но управление питается от AON, а U22 — от MAIN. Power-off isolation коммутируемых портов не защищает управляющие входы. Поэтому одного подключения провода выбора недостаточно. Перенос U22 на AON убрал бы конфликт напряжений, но мог бы оставить путь данных подключённым после провала MAIN без отдельной блокировки с доказанной задержкой MAIN-invalid. [onsemi, предельные значения и электрические таблицы, стр. 3–4](https://www.onsemi.com/download/data-sheet/pdf/fsusb42-d.pdf).

TI TS3USB221E — основной **ещё не выбранный** кандидат: питание 2,3–3,6 В, входная утечка управления нормирована при VCC=0 и VIN до 3,6 В, отдельно нормирована утечка отключённых портов. Он мог бы остаться на MAIN без конфликта управляющих напряжений FSUSB42. Это **не** доказывает поведение при `0 < VCC < 2,3 В`, не закрывает запас напряжения MAIN проекта и не квалифицирует SDIO. Распиновка невзаимозаменяема: контакты 1–10 — USB+, USB−, SDIO DAT2, SDIO DAT3, GND, OE, common−, common+, SEL, VCC. [TI TS3USB221E, стр. 3–6](https://www.ti.com/lit/ds/symlink/ts3usb221e.pdf).

Это доказательства для оценки снабжения, не электрическая приёмка; выбранные MPN повторно проверяются при заморозке и непосредственно перед заказом.

### Проверка выходной нагрузки

При условном AON 3,181696–3,376 В один R91=100 кОм ±1% нагружает высокий OE током до 34,10 мкА — больше табличных 20 мкА малой нагрузки HC20. Замена на 1 МОм уменьшает ток, но сама не доказывает VOH во всём диапазоне питания. **SN74LV20A**, не предполагаемый «74LVC20A», имеет совместимые контакты TSSOP-14 и гарантирует VOH≥VCC−0,1 В / VOL≤0,1 В при 50 мкА на всём VCC=2–5,5 В. Это кандидат для обоих NAND, не установленная замена. [Электрическая таблица HC20](https://assets.nexperia.com/documents/data-sheet/74HC20.pdf), [TI LV20A, разделы 3/4.5](https://www.ti.com/lit/ds/symlink/sn74lv20a.pdf).

Текущая страница [SN74LV20APWR / C2862070](https://jlcpcb.com/partdetail/TexasInstruments-SN74LV20APWR/C2862070), зафиксировано **2026-09-14T00:10:12Z**: Texas Instruments, Extended, SMT, Economic + Standard, склад 0, явный Pre-order, MOQ 21, предварительно $0,4265 за штуку; срок не установлен. Это не решение из наличия. Независимо от этого Q2 **2N7002DW** нормирует RDS(on) при затворе 5/10 В, не при предлагаемом гарантированном HIGH около 3,08 В. Порог затвора или типичные кривые при комнатной температуре не доказывают reset LOW. До внедрения нужно закрыть расчёт транзистора/утечек/температуры и перехода TCA9535 ко входам логики. [Электрическая таблица Diodes Q2](https://www.diodes.com/assets/Datasheets/2N7002DW.pdf). Сам диапазон AON остаётся допущением неквалифицированной модели питания.

## Незакрытые инварианты и следующий шаг

Завершить проверку выходной нагрузки управления и последовательности питания, затем внедрить одно согласованное нативное исправление: цепь драйверов, MPN/распиновка/footprint/bypass мультиплексора, исходные контракты и граница прошивки. Кандидат выше не доказывает изменение установленной схемы. Простое соединение REQUEST с SEL не является принятым исправлением.

Реальные задержки выключения мультиплексора и перехода площадок RP2354 в high-Z после reset, начальные состояния расширителя, запуск питания и горячее подключение/отключение ещё требуют полной проверки последовательности. Наблюдение уровня reset само по себе не измеряет задержку high-Z. Минимальный интервал break-before-make не является максимальной задержкой переключения; паузы 1 мкс из контракта ещё требуют обоснования. Нынешний Q3 также связывает подключение мультиплексора со снятием reset C5: это нужно согласовать с установкой strap-уровней и требуемым удержанием 3 мс.

Дифференциальная геометрия USB остаётся обязательной для общего участка в обоих режимах, одновременно с — а не вместо — целостностью одиночных сигналов SDIO, временными ограничениями всей группы CLK/CMD/DAT0–3 и существующими проверками 20/40 МГц/HIL. Этот отчёт не меняет PCB, MPN, прошивку или разрешение производства.
